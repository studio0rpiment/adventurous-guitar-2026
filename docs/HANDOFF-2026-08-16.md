## 1b. Participant photos

Two folders, on purpose:

```
assets-source/bioPics/   originals as sent — 1–12 MB camera files, never served
public/img/bioPics/      512x512 WebP, ~16 kB each — what the cards load
```

Everything under `public/` is copied verbatim into `dist/`, so a dozen originals
left there would have added ~40 MB to a deploy for thumbnails rendered at 52 px.

`scripts/bio-pic.py` does the conversion, driven by
`assets-source/bioPics/crops.json`:

```json
{ "KellyDoyle.jpg": { "out": "kelly-doyle", "focus": [0.465, 0.50], "zoom": 0.45 } }
```

`focus` is the fraction of (width, height) the square centres on — portraits
want y near 0.4 or the head gets cut. `zoom` is the crop's side as a fraction of
the shorter edge, so a full-body stage shot pulls in to 0.45 while a headshot
stays at 1.0. EXIF rotation is baked in rather than left to the browser.

New photo: drop the original in `assets-source/bioPics/`, add a line to
`crops.json`, run `python3 scripts/bio-pic.py`, and point the participant's
`image` at the output. The crop settings are recorded, so a re-run reproduces
exactly what shipped.

## 2. The scroll sequence

Page structure is `src/ui/InfoSections.tsx`:

```
.ags-hero-spacer     100svh   — the hero, canvas visible
IslandField                   — the programme islands
.ags-reveal-spacer   200svh   — EMPTY. This is the reveal runway.
```

The trailing spacer is load-bearing. Without it the page ended at the last
island and there was no scroll left in which to move the camera — the reveal
had to happen while an island was still on screen. The first viewport of it
carries the last island out of the top; the rest is the camera's descent.

`src/lib/scroll.ts` holds `scrollProgress()` and `smoothstep()`. Three things
read page scroll (camera descent, guitar mount gate, footer fade) and one
implementation means they can't disagree about where the bottom of the page is.

## 3. The camera descent (`src/three/CameraPan.tsx`)

**We move the camera, not the cables.** This is the single most important
decision in the file. The patch cables do their drag-and-seat maths by
raycasting from screen coordinates into *world* space — translating the cable
rig would put every plug out of register with its socket, so grabbing a plug
would drop it in the wrong hole. Moving the camera produces an identical
picture (cables travel up and out of frame) and leaves all of that correct for
free. It's a pure translation — no `lookAt`, so the framing doesn't tilt.

**Where the descent starts is measured.** It finds `.ags-island-field`,
computes the document-space Y of its bottom edge, and derives the scroll
fraction at which that edge passes the *top* of the viewport. So the guitar is
always beneath all the islands, however many the programme grows to. Read on
mount and resize only — no per-scroll layout thrash.

**Floor and rest height are functions of viewport, not constants.** A portrait
phone sees roughly twice the world-height a desktop does (same fov, camera
pulled way back to fit the width), so any fixed pan distance is wrong on one of
them. `floorY(halfHeight)` and `cameraRestY(halfHeight)` in
`src/three/guitar/layout.ts` derive both from `visibleHalfHeight()`, exported
from `ResponsiveCamera` so the framing maths has exactly one home.

The cables also **sag well below their sockets** — the ropes are slack. That's
`CABLE_SAG` (10 world units below the lowest socket). If cables ever dip back
into the guitar's frame, raise that number.

## 4. The floor guitar (`src/three/guitar/`)

**`FloorGuitar.tsx`** — gate + Suspense boundary. The model is 2.2 MB and only
appears at the bottom, so it isn't fetched during first paint; it mounts once
scroll passes `MOUNT_AT` (0.45), early enough that the download finishes before
it's needed. Note there is deliberately **no** `useGLTF.preload()` at module
scope — that would fire on import and defeat the gate.

**`Jaguar.tsx`** — static; it just lies on the floor and the camera comes to it.
Two things are measured rather than guessed:

- **Scale** — posed bounding box measured at scale 1, then scaled so its
  on-screen width is `WIDTH_FRACTION` (1 = edge to edge) of `visibleWidth()`.
- **Seat** — dropped so its lowest posed point lands exactly on `floorY()`.

Change the tilt or the viewport and it re-fits and re-seats itself.

**The model.** `public/models/fender_jaguar-web.glb`, 2.2 MB, down from the
43.3 MB Sketchfab original (kept alongside as `fender_jaguar.glb`). Textures
were only ~8 MB of that — the bulk was geometry, including four "Bolts" meshes
at ~3.4 MB each. Draco geometry compression + WebP textures, **no decimation**:
656,023 → 655,991 triangles. A simplified 1.2 MB variant was rejected because
the simplifier deletes the strings.

> **The Draco trap.** drei's `useGLTF` fetches its decoder from Google's CDN by
> default. When that request hangs, the loader never settles, the component
> suspends forever, and the guitar silently never appears — no error, no
> warning, just an empty scene. This cost real debugging time. The decoder is
> now self-hosted in `public/draco/` and passed explicitly via `DRACO_PATH`.
> **If you add another Draco-compressed model, pass that path too.**

**The jack anchor.** An empty group named `jaguar-jack` sits at the output jack,
found from the model's own `Plate_Jack` mesh rather than by eye. The cable work
should look it up and read its world matrix. Flip `DEBUG_JACK` to see it.

Open question for the cable: with the jack edge facing camera, a plug comes
almost straight at the viewer and may read as a foreshortened stub. Rotating
the guitar 15–20° off square (`POSE.rotation.y` nearer −1.3 than −1.57) would
give the cable somewhere to travel while keeping the side-profile read.

## 5. Navigation

The pick menu was hard to recognise as navigation, so there's now a plain nav
bar as well. Both drive the same `useNav` state; neither owns it.

- **`src/config/nav.ts`** — the items (see §1).
- **`src/ui/pickGeometry.ts`** — the fan's geometry, extracted from `PickMenu`
  because the mobile nav needs the *same* coordinates.
- **`src/ui/NavBar.tsx`** — desktop: a bar on the right. Mobile: a column beside
  the pick that **flies into the fan's label slots** when the pick opens, while
  `PickMenu` hides its own labels (`showLabels={false}`) so only one set of
  words exists. Landing positions come from `spokeLabelPos(i)`; each button's
  resting box is measured and the delta applied as a transform. Transform is
  cleared before measuring so deltas never compound.

`PickMenu` is now optionally controlled (`open` / `onOpenChange`) — `Hud` owns
that state because the mobile nav needs to know about it. It still falls back to
internal state if used standalone.

## 6. Footer (`src/ui/Footer.tsx`)

Fades in over the last 7% of scroll, pinned to the viewport bottom. A DOM
overlay, not 3D — the marks stay crisp and the canvas pays nothing. Opacity is
written straight to the element from the scroll handler; no React state, since
it changes on nearly every scroll event.

Three columns sharing **one bottom edge** (`align-items: end`) — mixed alignment
is what made it look ragged. Mobile stacks name over logo and keeps the SO
monogram bottom-right.

### Type gotchas, both real

**Monstera declares `hhea` descender = 0.** Its glyphs sit low in — and overflow
— their line box. Aligning the *boxes* of the monogram and the wordmark
therefore misaligns the *ink*. Anything set next to Monstera will hit this.

**The alignment rule is baseline, not ink box.** Centring the ink boxes put the
descender of the "p" in "Orpiment" level with the bottom of the SO, which reads
as the word floating high. The wordmark's last baseline now meets the
monogram's ink bottom. The solved value is `0.025em`; `--credit-trim` (4px) is
the separate by-eye adjustment on top, kept separate because browsers resolve
half-leading slightly differently.

**Rotor is variable**: `wght` 100–900, `RTTX` 0–360 (rotates each letter),
`DPTH` 20–600 (unused, left at 200). The wordmark sits at `wght` 100 and hover
turns the letters only — the weight axis is deliberately out of the transition.
Staggering axes needs registered custom properties (`@property --ags-rttx`,
`--ags-wght`): `font-variation-settings` is one property, so a plain transition
moves every axis on one clock.

**The Shepherd PNG is navy on transparent** and would vanish on `#0a0a0f`;
`filter: brightness(0) invert(1)` flips it to white with alpha intact. Worth
asking Chapman for a reversed lockup so the filter can go.

## 7. Tuning knobs

| What | Where |
|---|---|
| Pick + fan overall size | `S` in `src/ui/pickGeometry.ts` (1.157625 = 3×5% up) |
| Title lockup height / exit speed | `CY`, `RISE` in `TitleText3D.tsx` |
| Island overlap + width per breakpoint | `--ags-island-w`, `--ags-island-overlap` in `global.css` |
| Reveal runway length | `.ags-reveal-spacer` height (200svh) |
| Cable sag allowance | `CABLE_SAG` in `guitar/layout.ts` |
| Guitar height in final frame | `FRAME_BIAS` (0 = floor on centre line) |
| Guitar width | `WIDTH_FRACTION` (1 = edge to edge) |
| Guitar pose | `POSE.rotation` |
| Footer fade start | `FADE_START` in `Footer.tsx` |
| Wordmark vertical nudge | `--credit-trim` in `global.css` |

## 9. Conventions held throughout

- **Event-driven over timers.** Everything here hangs off scroll, resize,
  pointer or media-query change. There are no polling loops.
- **Derive, don't duplicate.** Nav items, fan geometry, framing maths, floor
  height and participant ordering each have exactly one home; the second copy
  is what drifts.
- **Measure, don't eyeball.** Model bounds, jack position, viewport fit, nav
  flight targets and type alignment are all read at runtime or from font
  metrics rather than hard-coded from a screenshot.
- **No per-scroll React state.** Scroll handlers write to refs or straight to
  `element.style`; re-rendering the tree per pixel is wasteful.
